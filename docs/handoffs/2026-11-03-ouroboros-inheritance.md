## Goal and problem

Each generation should build on the genome it inherits. Previously, fork and template creation appended ancestor guidance to the codebase outline, then passed the combined text through `condensedOutline()`. That function retained selected outline lines and stopped around its compaction threshold, discarding the inherited guidance. The genome survived in SQLite, but the model did not receive the intended context.

Ordinary cycles inherited genome rows without adding their parent context to analysis at all. The reviewer also received an abbreviated outline without inherited guidance.

## Changes delivered

In [server/intelligence/ouroboros-cycle.js](../../server/intelligence/ouroboros-cycle.js):

- `analyzeForImprovements(outlineText, genomeContext)` compacts the outline first and appends inherited context separately.
- `reviewProposals(proposals, outlineText, genomeContext)` receives the same inherited context outside the abbreviated outline.
- `runCycle()` constructs parent context from the child's inherited active genome.
- `forkCycle()` sends the explicitly selected ancestor's context through both model stages.
- `instantiateTemplate()` sends the saved template genome through both stages, even when the source cycle has changed since the template was saved.
- Prompt wording calls these patterns "accepted" rather than "proven"; proposal acceptance alone is not execution validation.

No schema migration or new dependency is required. Existing genome data can be used by the corrected path after backend restart. Existing historical generations are not regenerated by this change.
